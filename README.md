# 取引記録ツール

FX・暗号資産（BTC/USD など）の取引を**カレンダーに書き込んでいく**ツールです。
月グリッドの日付をクリックして、その日の損益とメモを記録します。

- 記録は手元の `trades.json` にのみ保存されます（外部送信なし）
- 損益はドル建てで保持し、円換算は設定の USD/JPY レートで行います

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 画面

| ページ | 内容 |
| --- | --- |
| **カレンダー** | 月グリッドで入力。勝ち🟩／負け🟥の色分け、前月・翌月の切り替え、その日の記録の追加と削除 |
| **日報** | 結論 → 根拠 → 次のアクション の3部構成レポート、累計と想定ラインの比較 |
| **分析** | 勝率・PF・期待値・最大DD、銘柄別 / タグ別 / 曜日別の成績 |

カレンダーのマスをクリックすると下に入力欄が開きます。**必須なのは損益の金額だけ**で、
銘柄・方向・エントリー/決済/SL は「銘柄・価格も残す（任意）」を開いたときだけ入力します。

## 入力形式（CLI）

CLI は自由記述を解釈します。**必須なのは損益の金額だけ**です。

```
今日の利益：15ドル、メモ：押し目買いで勝ち
BTC/USD 買い +15ドル メモ：H1上昇の押し目 タグ：押し目 順張り
USD/JPY 売り -8ドル 手数料0.4ドル タグ：早仕掛け
BTC/USD 買い エントリー64000 決済64500 SL63800 TP64600 +25ドル
```

認識するラベル（数値ラベルは直後に数字が続く場合のみラベルとして扱うため、
メモ本文に「利確が早すぎた」と書いても誤認しません）。

| 項目 | 書き方 |
| --- | --- |
| 損益 | `利益：15ドル` / `損益：-8ドル` / `+15ドル` / `マイナス12.5ドル` |
| 銘柄 | `BTC/USD` `USD/JPY` のようなスラッシュ区切り |
| 方向 | `買い` `売り` `ロング` `ショート` `BUY` `SELL` |
| 価格 | `エントリー` `決済` `SL` `TP` |
| その他 | `ロット` `手数料` `メモ：` `タグ：`（スペース区切りで複数） |

エントリー・SL・決済が揃っていれば **R倍（r_multiple）** と**当初の RR** を自動計算します。

## CLI

```bash
python cli.py add "BTC/USD 買い +15ドル メモ：押し目買い"   # 記録して日報を表示
python cli.py add "今日の利益：8ドル" --date=2026-08-24     # 日付を指定
python cli.py report            # 今日の日報
python cli.py month             # 月次サマリー
python cli.py list --month=2026-08
python cli.py undo              # 直近1件を取り消し
python cli.py rm t00007         # ID 指定で削除
python cli.py config usdjpy=150 monthly_goal_jpy=80000
```

## 設定

サイドバー、または `python cli.py config キー=値` で変更します。円建てを正とし、
ドル建ての目標は `usdjpy` から自動換算します。

| キー | 既定値 | 意味 |
| --- | --- | --- |
| `monthly_goal_jpy` | 100,000 | 月間利益目標（円）。@155円 で約 645 ドル |
| `seed_jpy` | 50,000 | 維持したい種銭（円）。@155円 で約 323 ドル |
| `usdjpy` | 155.0 | 円換算レート |
| `trading_days` | 30 | 月の稼働日数 |
| `risk_per_trade_pct` | 2.0 | 1トレードの許容リスク（口座残高に対する%） |
| `max_drawdown_pct` | 20.0 | 種銭に対して許容するドローダウン（%）。超えると日報が警告を出す |

## 配布用の1枚 HTML（人に渡す版）

`web/ledger.html` は、Python もサーバーも不要で動くカレンダー台帳です。
記録は**開いた人のブラウザにだけ**保存されるので、リンクを配っても記録は混ざりません。

タブは2つあります。

| タブ | 内容 |
| --- | --- |
| **台帳** | 月カレンダーで日々の損益を記録。カテゴリー別収支・達成率・必要ペース・日報 |
| **入出金** | 口座への入金と出金。円で入れるとその時の USD/JPY でドル換算して記録 |

記録には区分（カテゴリー）を付けられます。**FX / 暗号通貨 / バイナリー / stake** から選ぶか、
「その他」で自由に入力できます（入力した名前はそのまま集計の見出しになります）。
台帳タブの「カテゴリー別 収支」に、その月の区分ごとの件数・勝率・損益が並びます。
区分を付けずに記録したものは「未分類」にまとまります。

残り日数と想定ラインは**カレンダー基準**です（月末までの実日数）。記録しなかった日も
過ぎれば戻らないため、「稼働日数 − 記録した日数」では数えません。
`trading_days` は計画ペース（1日あたりいくら狙うか）の分母としてのみ使います。

種銭は**円とドルのどちらでも**入力できます（「目標設定」の円／ドル切り替え）。
口座がドル建てなら**ドルで持つ**のが確実です。円で持つとレートを更新するたびに
元本のドル額が動いてしまうためです。切り替えたときは、そのときのレートで金額を換算します。

口座残高は **投入元本（種銭 ＋ 入金 − 出金）＋ 全期間の損益** で計算します。
入出金を記録しないと、入金した分が「勝ち」として数えられてしまうので注意してください。

```bash
python scripts/build_page.py     # web/ledger.html -> docs/index.html
```

`docs/index.html` は単体で完結しているので、そのまま静的ホスティングに置けます。

**GitHub Pages で配る**

1. リポジトリの Settings → Pages を開く
2. Source を `Deploy from a branch`、Branch を `main` / `/docs` にして Save
3. 数分後 `https://<ユーザー名>.github.io/mtf-tool/` で公開される

**独自ドメインで配る**

取得済みのドメインがあれば、Settings → Pages → Custom domain に入力し、
DNS 側に CNAME（`www` → `<ユーザー名>.github.io`）または A レコードを設定します。
`docs/CNAME` にドメイン名を1行で置くと設定が保持されます。

データを端末間で移すときは、右下の「バックアップを保存」で JSON を書き出し、
移行先で「読み込む」から選びます（同じ記録は二重に入りません）。
